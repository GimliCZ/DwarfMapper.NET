# Round 31 T19 — projection, startup, P8 and T15 measurements (2026-09-27)

Windows 10, local 12-core box, BenchmarkDotNet ShortRun (1 launch, 3 warmup, 3 iterations) except the startup class
(ColdStart, 5 launches x 1 invocation — a fresh process per registration). **ShortRun: read ratios, not absolute times.**
"Before" arms are the old emitted shapes written out by hand, in the same process (the LegacyAmbientFacade convention).

- DTO lists: twin 7.5 µs vs pre-sized general loop 6.6 µs at 1,024 (1.14x) — **under the threshold**.
- Same-type value lists: a copy is 2.7x faster than `Select(x => x).ToList()` — but only if the twin's text ever contains
  that identity Select; not verified to occur, so not a basis for a task.
- Widening `int[] → List<long>`: the GENERATED path (`DwarfM.MapNumList`) is **1.6x slower** than `Select(x => (long)x).ToList()`
  at 1,024 elements (739 vs 465 ns, same allocation). Not a T15 question — a **new finding** for round 32: the value-element
  widening fill the generator emits loses to LINQ here.
- **Decision: T15 is not built.** Its premise (general mapping beats the twin's Select for nested collections) did not
  clear the threshold for DTO elements, and for widening it is the other way round.

  Recorded because it changes T11's justification: the quadratic it fixed was fixed again, more generally, by T14.
