# Round 24 — auditing the generator's own output with static analysis (I21)

Filed 2026-08-23. Closes the measurement half of `Issues/round20/TASKS.md` **I21**; leaves the
always-on-gate half open with a named blocker.

## The premise, and the correction to it

I21's framing is right and the `<PropertyGroup>` in it is **necessary but not sufficient**:

```xml
<EmitCompilerGeneratedFiles>true</EmitCompilerGeneratedFiles>
<CompilerGeneratedFilesOutputPath>$(BaseIntermediateOutputPath)generated</CompilerGeneratedFilesOutputPath>
```

That writes files to disk. It does **not** make analyzers read them. `MapEmitter.cs:14` and
`DwarfGenerator.cs:271` write `// <auto-generated/>` as the first line of every emitted file, which is
exactly what Roslyn's analyzer driver reads to classify a file as generated and skip it. Overriding that
verdict — `generated_code = false` scoped to the emitted path — is the half that does the work. The two
halves are orthogonal.

**Proved by control, not assumed.** With the emission property on and the `.editorconfig` override
absent: `0` warnings across 571 emitted files. With the override added: 1,092. The premise holds.

### Where the property must live

`Directory.Build.props` is imported **before** the SDK defines `BaseIntermediateOutputPath`, so there
`$(BaseIntermediateOutputPath)generated` evaluates to a bare `generated` — a directory in the PROJECT
ROOT, which the SDK's `**/*.cs` glob then compiles as ordinary source. Measured, not theorised: 2,004 ×
CS0111 and 1,084 × CS0757 across the solution. It belongs in `Directory.Build.targets`, imported after
the SDK props. It is now there, Debug-only, so Release stays clean for the reproducible-build and
package-size gates.

## The defect it found, and fixed

Two emitters disagreed about one contract:

| Emitter | Emitted null guard |
|---|---|
| `MapEmitter` | `global::System.ArgumentNullException.ThrowIfNull(source);` |
| `MapToGenerator` | `if (source is null) throw new global::System.ArgumentNullException(nameof(source));` |

One product, two idioms, same TFM. Invisible by construction: both compile, so the compiler is silent,
and a snapshot pins whatever it is handed. `MapEmitter` documents why the helper form is right (the
`throw` lives in a `[DoesNotReturn]` helper, so the hot method stays small IL and inlines; an inline
`throw` can block inlining) and that argument applies at least as strongly to `[MapTo]`'s extension
methods.

`MapToGenerator` already carried the comment *"the two sites disagreeing is exactly how this path came to
differ from the nested-helper one"* — it guarded divergence WITHIN itself and never saw the divergence
from `MapEmitter`.

Fixed at both sites. `RegistryValueTypeSourceTests.A_reference_type_source_keeps_its_null_guard` counted
the inline string; its stated intent is "two methods, two guards", so it now counts the helper form AND
asserts the inline form is absent — the previous assertion passed on either idiom, which is why the drift
survived. Golden manifest and five Verify snapshots updated; every delta reviewed and null-guard-only.

## Filed, not forced

**CA1852 — seal the types the generator OWNS.** True for the co-located `[GenerateMap]`-on-a-DTO path,
which invents e.g. `PersonDtoMapper`. False for a declared mapper, which is the consumer's own
`partial class`: one part carrying `sealed` seals the whole type and breaks any consumer deriving from
their own mapper. `MapEmitter` emits one class header (`MapEmitter.cs:36`) for both cases and
`MapperClassModel` carries no flag distinguishing them. Adding one means touching a record that is an
incremental-generator cache key, where equality is load-bearing. Worth doing; not worth doing carelessly.

**CA1508 — the emitted double read.** One site:

```csharp
if (src.Count is not null) dst.Count = src.Count ?? throw new InvalidOperationException("Source member 'Count' was null");
```

`SkipNullSourceMembers` supplies the guard; the nullable→non-nullable coercion supplies the coalesce.
The compiler is right that the fallback is unreachable after the guard — but the two `src.Count` are
separate property invocations, so the coalesce is defence against a source property returning null on the
second read, and throwing there is this library's stated posture. The strictly better emission reads the
member ONCE into a local, removing the dead branch and the double read together. That changes behaviour
in the mutating-property corner (throw → use the first value), so it is a maintainer's call.

## The blocker for an always-on gate

`generated_code = false` works. **Severity scoping inside the same section does not.** With
`dotnet_analyzer_diagnostic.severity = none` plus per-rule `dotnet_diagnostic.CA1822.severity = none` in
`[**/generated/DwarfMapper.Generator/**/*.cs]`, CA1822/CA1508/CA1707/CA1852/CA1859 still fire, while
MA0192 and CA2255 are correctly silenced by the same bulk setting. So the section is matched and partly
honoured — some rules resist it. Under `TreatWarningsAsErrors` that means enabling the override
repo-wide turns 1,066 intent findings into build errors.

Until that is solved, the audit is **on demand, not always-on**, and reproducible:

1. add the `[**/generated/DwarfMapper.Generator/**/*.cs]` section with `generated_code = false`
2. `dotnet build DwarfMapper.NET.sln --no-incremental -p:TreatWarningsAsErrors=false`
3. read diagnostics whose path contains `generated/DwarfMapper.Generator`
4. remove the section

Emission itself stays on in Debug, so the output is always on disk to read and diff — which is the half
that costs nothing and is useful on its own.
