## Per-entry verdicts

### R22-00 (type-graph gen + renderer) — ADOPT, with corrections

The right foundation, and the coverage-ratchet companion (generator's kind/shape enums must cover every
surface-matrix dimension, ratcheted) is exactly the house anti-allowlist move. Defects to fix at
implementation:

- `Assemble(((TypeKind k, MemberSpec[] ms))[] raw)` is a **syntax error** (parenthesized one-element tuple
  type); the RFC was honest that nothing was compiled — treat all code as sketch.
- The `SEAM` validity rules are the real work and are *understated*: besides acyclic NestedRef, name dedupe,
  `required`×CtorParam and struct×BaseRef, the rules must forbid **value-type cycles through NestedRef**
  (a struct containing itself = CS0523, uncompilable regardless of the mapper) — this also bites R22-02's
  MR-3 re-kinding, whose SEAM guards only struct+BaseRef.
- Member names `M{rand 0-9999}` need dedupe *per node* (acknowledged) and the oracle's population must be
  **name-keyed, not declaration-order-keyed**, or MR-1's reorder relation fails spuriously.

### R22-01 (differential vs reflection oracle) — ADOPT; the strongest entry. Integration corrections:

- **Sequencing:** leg 1 ("silent + CS errors = red") will trip immediately on the 10 known
  `EmittedInvalidCode` cells (B27=8, B33=2) until round-21 T6 closes them. Either land after T6, or land
  with a `DeclaredDivergences`-style shrink-only allowance keyed to those two issue ids — never a blanket
  skip.
- **Reuse, don't rewrite:** `GraphDeepCompare`/member-path diff already exists in substance as the
  `[RoundTrip]` differ inside the shipped `DwarfMapper.Testing` package. Using it dogfoods the shipped
  testing surface (its own TestingOnly obligation) instead of growing a parallel test-side comparer.
- The reflection oracle is test-side, public-members-only, deliberately naive — this does NOT violate the
  house no-reflection stance (which governs the shipped product's accessibility behaviour, not test
  oracles). Stated here so nobody relitigates it.
- "One oracle switch per documented option" = a spec-completeness ratchet. Good; it is the same philosophy
  as `DeclaredDivergences` and should share its shrink-only discipline.

### R22-02 (metamorphic relations) — ADOPT with the MR-3 cycle guard and name-keyed population above.

MR-1 (member order), MR-2 (unmapped-member neutrality) are sound and cheap once R22-00 exists. Note MR-2
must pin the base config (no explicit-only/strict modes) or additions legitimately refuse.

### R22-03 (all-tracked-steps caching contract) — ADOPT NOW, independently; fold into ROUND 21.

Verified: the existing `IncrementalCachingTests` asserts an **allowlist of named steps** (Extract,
SourceOutput, CoLocatedExtract...). The RFC's delta — enumerate ALL `TrackedSteps`, no allowlist, so a new
pipeline stage is covered on arrival — is precisely the drift mode this repo exists to delete, it needs
none of R22-00's infrastructure, and it costs milliseconds. This is the one entry that should not wait for
round 22.

### R22-04 (mutation gates) — REJECT as written.

Built on the two falsified claims above. Additionally its philosophy ("break = measured − 4, green on day
one") **contradicts the established house rule**: break = the measured floor exactly, moved only with a
re-measurement in the same commit (a rule enforced three times in rounds 20–21). Salvage: the per-subsystem
matrix idea (generator + doctooling legs in CI alongside runtime) is already T5's scope; nothing else
survives.

### R22-05 (SharpFuzz coverage-guided) — DEFER, agreeing with the RFC's own trigger discipline.

Adopt only when R22-01's random sampling saturates. The genuinely good idea to keep: **seed the fuzzer's
corpus from the surface matrix's enumerated cases** — the hand-built matrix becomes the starting
population. Also note SharpFuzz instrumentation wants the generator DLL isolated, which the RFC's
separate-project layout already anticipates.

## Cross-cutting constraints the RFC could not know (round-21 state)

1. **Budget collision.** The deep tier already carries 39:24 of mutation against the 44-min ceiling (H6).
   R22-01 at 1,000 iters ≈ 1,000 generator runs + Roslyn emits — minutes, not seconds; 10,000 nightly is
   its own leg. The RFC's counts cannot simply be added to the nightly; T5 must arbitrate (alternating
   nights, or the differential leg replacing part of the mutation cadence). No entry lands without a
   measured wall-clock, per the round-21 rule that every tool is RUN with measured output.
2. **The `DWARF_DEEP` knob (T4)** is the intended home for the iteration counts — fast tier runs a smoke
   count (tens), deep tier the full count. The RFC's "nightly leg raises to 10_000" comment should be that
   knob, not a copy of the test.
3. **RepoWriteGuard / ARCH-06 scan (H1, landed 2026-08-19):** the new CompilerTests project's tests write
   no repo files, but any raw file-write API use in `tests/` now must be registered with a reason — the
   new project inherits that scan automatically. Design for it (temp dirs only).
4. **Timeout discipline (H7, maintainer directive):** any loop the new harness adds (graph assembly,
   population, compare) must be provably terminating or progress-guarded — no test may rely on a clock to
   fail.
